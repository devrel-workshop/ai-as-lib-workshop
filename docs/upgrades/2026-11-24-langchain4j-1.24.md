# LangChain4j 1.23.0 → 1.24.0, Quarkus 3.40.1.1 → 3.40.1.2, MCP server 2.0.4 → 2.1.0, logback 1.6.6 → 1.6.8

**Scope:** both chatbot tracks (`workshop/` and `solutions/`), snippets, READMEs, `CLAUDE.md` · audio module out of scope
**Java release:** 25 (`//JAVA 25+`, `maven.compiler.release` 25) · built and run here on Temurin 26
**Verdict:** drop-in bumps on both tracks, no code change required. None of the 1.24.0 breaking changes touches an API the workshop calls, nothing it uses was deprecated or removed, the tool error handler defaults announced in 1.21 have still not changed, and the documentation pages the exercises follow describe the same APIs. The MCP server 2.1.0 is a minor with breaking changes on the server side; none applies to module 4, and the LangChain4j client still negotiates the stateless `2026-07-28` protocol against it.

## Verification

1. **After the LangChain4j bump:** `bin/preflight.sh --only jbang` 18/18.
2. **Compile lint:** the 9 solution scripts at 1.24.0 with `-Xlint:deprecation -Xlint:removal`: 0 warnings, 0 errors.
3. **After the Quarkus bump:** `bin/preflight.sh --only quarkus` 2/2; `mvn dependency:list` resolves quarkus-core 3.40.1.2, quarkus-langchain4j-core 1.13.4, langchain4j-core 1.19.3.
4. **After the MCP server bump:** `bin/preflight.sh --only quarkus` 2/2; the solution jar bundles `quarkus-mcp-server-{core,http}-2.1.0`.
5. **MCP interop** (solution jar on Quarkus 3.40.1.2 + MCP server 2.1.0, client `langchain4j-mcp` 1.24.0-beta34 over `http://localhost:8080/mcp`): `server/discover` with protocol `2026-07-28` (modern protocol), response carries `serverInfo` in `_meta`, then `tools/list` returns `generateImage` with both argument descriptions. No 400/404.
6. **Snippet regeneration:** YAML diff 1 line, generated diff 1 line.
7. **`bin/e2e.sh --with-agentic`** against AI Endpoints (`gpt-oss-120b`), all bumps applied: 11/11. Simple, streaming, memory and RAG answered (RAG quoted the room, "Hands-on", read from the indexed file); the tool chatbot, the agent loop, the supervisor and the MCP chatbot through the Quarkus server on MCP server 2.1.0 each produced real image bytes; the three Quarkus REST endpoints answered HTTP 200.
