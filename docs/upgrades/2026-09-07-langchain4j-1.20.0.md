# LangChain4j 1.19.0 → 1.20.0 (JBang track)

**Scope:** `workshop/chatbot/java/java-langchain4j`, `solutions/chatbot/java/java-langchain4j`, the `java-35`/`java-36` snippets and the LangChain4j README · Quarkus track untouched (see below) · audio module out of scope
**Intermediate releases included:** `1.19.2` / `1.19.2-beta29` (the real `1.19.x` patch) · `1.19.1` / `1.19.1-beta29` deliberately **excluded** — see "Version resolution"
**Project:** 9 JBang scripts × 2 trees, versions declared directly in `//DEPS` · **Java release:** `//JAVA 25+` (built here on Temurin 26) · **Version managed by:** direct
**Verdict:** Drop-in bump. Every API the workshop uses is unchanged in 1.20.0, nothing it uses is deprecated, and the release is verified green by `bin/preflight.sh` and `bin/e2e.sh`. The code changes made alongside are best-practice alignments with the official MCP page (static builder factories, closing the client); they are not caused by the bump and can be reverted alone. An audit of every workshop pattern against the live documentation is included below.

**`1.19.1` is a trap.** Its GitHub release note says it was cut from `main` by mistake and contains all of `1.20.0` plus three later commits, despite the lower number. Maven Central is immutable, so it stays published. Never pick it as a baseline or a target; the intended `1.19.x` patch is `1.19.2` (= `1.19.0` + the MCP backports of [#6329](https://github.com/langchain4j/langchain4j/pull/6329)). A project on `1.19.1` must go to `1.20.0+`, never "up" to `1.19.2`.

**The Quarkus track is not bumped here, on purpose.** Platform 3.39.1 pins quarkus-langchain4j 1.13.0, which pins `dev.langchain4j` 1.19.0. Overriding that to 1.20.0 would produce a combination the extension never tested. After this change the two tracks run different LangChain4j versions (1.20.0 vs 1.19.0) until a platform release carries a quarkus-langchain4j built on 1.20.0 — the interop between them (module 4 client ↔ module 6 server) is verified below and unaffected.
