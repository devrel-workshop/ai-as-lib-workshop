# LangChain4j 1.20.0 → 1.22.0, Quarkus 3.39.1 → 3.40.1, MCP server 2.0.0 → 2.0.3, logback 1.5.38 → 1.6.5

**Scope:** both chatbot tracks (`workshop/` and `solutions/`), snippets, READMEs, `CLAUDE.md` · audio module out of scope
**Java release:** 25 (`//JAVA 25+`, `maven.compiler.release` 25) · built and run here on Temurin 26
**Verdict:** drop-in bumps on both tracks. The only visible effect of a bump is a startup warning added in LangChain4j 1.21 for AI Services with tools, silenced by declaring the current error-handling defaults explicitly. The audit also produced three fixes and a cleanup that are independent of the bumps and can be reverted alone.

## Verification

1. **Baseline** `bin/preflight.sh` on the old versions: 20/20.
2. **After each commit:** `bin/preflight.sh --only jbang` (18/18) or `--only quarkus` (2/2, with tests); **final** full run: 20/20.
3. **Compile lint** (scratch copy, `-Xlint:deprecation -Xlint:removal`): 0 warnings, 0 errors on the 9 solution scripts at 1.22.0.
4. **WARN check** (offline, unreachable model): HEAD before commit 2 prints the notice, after commit 2 it does not; both reach the prompt.
5. **MCP interop** (solution jar on 3.40.1 + MCP 2.0.3, LangChain4j 1.22.0-beta32 client): `server/discover` advertises `2026-07-28` first; `tools/list` returns `generateImage`. Re-run after commit 7 to confirm the descriptions.
6. **Quarkus prod jar** (scratch, fake OpenAI stub): `/chatbot/simple`, `/advanced`, `/memory` answer; outgoing request carries `max_completion_tokens: 50000`, `temperature: 0.2`.
7. **Snippet regeneration:** every generated diff matched its YAML diff line for line.

## Not verified — check before the next event

- **`bin/e2e.sh` was not run** (needs the real token and costs credits). Run it, or the `e2e.yml` workflow, before the next session — in particular `--with-agentic`, since the agentic planner and summarizer changed in 1.21.
- A real `tools/call` end to end (needs the SD endpoint): covered by `bin/e2e.sh --only mcp`.
- A native build with the new `quarkus.native.enabled` property (needs GraalVM/Mandrel); only the effective POM was checked.
- The code-server CDE proxied path. Both `application.properties` set `quarkus.http.host=0.0.0.0`, which keeps Host validation and the MCP `Origin` check inactive, but this was not exercised through the proxy.
- Whether `quarkus ext add io.quarkiverse.mcp:quarkus-mcp-server-http` (suggested in the Quarkus README) now resolves its version through the platform BOM.
- On JDK 26 only, Jackson triggers a `Final field … mutated reflectively` warning (JEP 500) in the MCP client; attendees on Java 25 do not see it.
